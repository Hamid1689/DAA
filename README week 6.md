# Maximum Depth of Binary Tree

## 1. Problem

Дано бинарное дерево. Нужно найти его максимальную глубину: сколько узлов на самом длинном пути от корня вниз до самого дальнего листа.

Пример: `[3,9,20,null,null,15,7]` даёт ответ `3` (путь 3 → 20 → 15).

Скриншот решения на LeetCode: `screenshot.png`

## 2. Approach

Использую рекурсию. Глубина дерева равна 1 (сам корень) плюс глубина более глубокого из двух поддеревьев:

```
maxDepth(node) = 1 + max(maxDepth(node.left), maxDepth(node.right))
```

Если узла нет (`null`), его глубина 0. Это база рекурсии.

### Код

```java
class Solution {
    public int maxDepth(TreeNode root) {
        if (root == null) {
            return 0;
        }
        int left = maxDepth(root.left);
        int right = maxDepth(root.right);
        return Math.max(left, right) + 1;
    }
}
```

### Трассировка на примере `[3,9,20,null,null,15,7]`

```
maxDepth(3)
  maxDepth(9)
    maxDepth(null) = 0
    maxDepth(null) = 0
    -> max(0,0) + 1 = 1
  maxDepth(20)
    maxDepth(15) -> 1
    maxDepth(7)  -> 1
    -> max(1,1) + 1 = 2
  -> max(1,2) + 1 = 3
```

Ответ: `3`.

Второй пример, дерево-цепочка `[2,null,3,null,4,null,5,null,6]`: у каждого узла только правый ребёнок, поэтому глубины складываются 1 + 1 + 1 + 1 + 1 = `5`.

### Трудности и что не сработало

> Перепиши этот раздел своими словами по тому, что реально было у тебя.

- Сначала я хотел считать число всех узлов, но это не глубина: в дереве из 7 узлов глубина может быть 3, а может быть 7.
- Забыл, что нужно взять **максимум** из левой и правой глубин, а не сумму. Сумма давала слишком большие числа.
- Не сразу понял, что для `null` нужно возвращать 0, а не 1. Иначе к ответу прибавлялась бы лишняя единица.

## 3. Complexity

**Time Complexity: O(n)**, где n это число узлов. Каждый узел посещается один раз, и на узел тратится постоянное число операций (сравнение и прибавление единицы).

**Space Complexity: O(h)**, где h это высота дерева. Это глубина стека рекурсивных вызовов.
- В сбалансированном дереве h ≈ log n.
- В худшем случае (цепочка) h = n, то есть O(n).

## 4. Reflection / Improvement

- **Можно ли быстрее?** Нет, по времени O(n) это минимум: чтобы узнать глубину, надо увидеть все узлы.
- **Другой подход:** обход в ширину (BFS) с очередью. Идём по уровням и считаем, сколько уровней прошли. Время тоже O(n), память O(w), где w это максимальная ширина дерева.
- **Что изменить:** вместо рекурсии использовать очередь `Queue<TreeNode>` и счётчик уровней. Он помогает избежать глубокой рекурсии на очень длинных деревьях (риск `StackOverflowError`), но по сложности выигрыша нет.
